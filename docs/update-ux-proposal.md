# 插件更新体验方案（UI 驱动 / 手动重启）— 2.8.x 提案

> 依据：用户 2026-11-22 要求「不要闭门造车，先看别人插件怎么做更新」。本文是调研 + 结合本插件现状的可行性判断，不含代码改动。

## 1. 外部惯例（调研结论）

| 产品 | 检查 | 下载 | 生效时机 | 用户确认 |
| --- | --- | --- | --- | --- |
| VS Code 扩展 | 自动（默认延迟 12h 才装新版本；`extensions.autoUpdateDelay` 可调） | 后台 | 装完即生效（扩展宿主进程重载） | 无（可关自动更新/手动立即更新） |
| Obsidian 社区插件 | **手动**（设置里「检查更新」/单个「更新」） | 点更新时下载 | 立即生效（无进程重启） | 每次都要点 |
| Electron 应用（electron-updater） | 自动（后台） | 后台静默下载 | **必须 `quitAndInstall()`**；惯例是下载完成后弹窗「重启以完成更新」 | 有（弹窗里点「立即重启/稍后」） |
| Rytora Code Updater（Open VSX） | 定时 | 后台预下载 | 提示「需要重启时」才重启 | 有 |

共同点（可直接借用）：
1. **检查与下载是后台的，生效（重启）必须由用户点头**——没人会不经确认就重启别人正在用的应用；
2. **版本信息展示在「关于/详情/插件卡」这类地方**，而不是弹窗轰炸；
3. **「稍后」要能真正延后**（不重复弹）；
4. 发布侧要有一个稳定的「最新版本」来源（VS Code 走 Marketplace API，Electron 走 update feed，Obsidian 走 community-plugins.json）。

## 2. 本插件现状（已具备的）

- `latestReleaseVersion()`（`lib/index.js:131`）读 GitHub tags，10 分钟缓存，失败静默；doctor 暴露 `latestVersion` / `updateAvailable`（`:4404-4413`）。
- 面板已有「有新版」提示（`lib/client.js:2259-2263`），文案是「去插件市场/Release 升级后重启 DSH」——**只提示，不落地**。
- 安装侧已成熟：`install-agent-worker.ps1` 原子切换 + 安装清单 + SHA256 复核 + 失败回滚；`maintenancePkgDir` 可从共享盘取包；`upgrade` 维护动词可远程装包（2.7.9 起安装目标已修正为插件目录）。
- 缺的是：**从公网取包**、**机器卡展示版本/可用版本**、**安装后不自动重启**、**重启按钮**。

## 3. 建议方案（用户提的版本 + 调研校准）

### 3.1 数据面
- 版本来源优先级：npm registry（`@wfcj/dsh-job-board` 的 `dist-tags.latest` + `dist.tarball`）→ 失败回退 GitHub tags（现状）。两者都缓存 10 分钟，后台刷新。
- 每台机器上报自己 `pluginVersion`（已有：worker 每次 beat 带 `version`），主控在机器卡显示「v2.7.11」；与「最新」不一致时显示 `⇢ v2.7.12 可用`。

### 3.2 交互（机器卡）
1. 机器卡显示当前版本；有新版时出现「安装更新」按钮（默认**不自动装**）。
2. 点「安装更新」→ 主控把任务排到该机器（复用维护通道 `upgrade` 动词；包来源：主控下载到共享盘，或副机直接从 npm 拉——后者要求副机可出网，GT14/PC2 当前走共享盘更稳）。
3. 安装完成 → 卡片状态变「已安装 v2.7.12 · 待重启」，按钮变「重启 DSH」。**不自动重启**。
4. 点「重启 DSH」→ 复用 2.7.11 的 helper（按 exe 路径杀 + 拉起 + 日志），面板显示「正在重启…」并轮询 `doctor`，回来后显示新版本。
5. 可选「自动安装」开关（按机器）：勾选后后台装、仍不重启；「重启」永远手动。

### 3.3 安全与兼容
- 只允许「主控 → 副机」方向触发安装；token + 票据校验沿用现有维护通道。
- 安装前校验：包名/版本/`install-manifest`/关键文件 SHA256；失败自动回滚（已有）。
- **DSH 本体升级后的兼容问题**：插件 `inject` 的服务（webServer/tools/agentLoop/sessions）由宿主提供，DSH 大版本升级可能改签名 ⇒ 建议在 doctor 里增加 `dshVersion`（宿主版本），发布说明写明「本插件适配 DSH x.y+」，且更新流程里先比对宿主版本再决定是否提示升级。
- 回滚：保留 `.bak-<stamp>` 目录 + 一键 `rollback-<machine>.ps1`（已有）。

## 4. 可行性结论

| 能力 | 可行性 | 成本 |
| --- | --- | --- |
| 机器卡显示版本 + 可用版本 | 高（数据都有，只差 UI） | 0.5 天 |
| 点按钮安装（npm/共享盘取包） | 高（维护通道 + 安装器已成熟） | 1 天 |
| 安装后手动点重启 | 高（2.7.11 helper 已落地） | 0.5 天 |
| 「自动安装但不重启」开关 | 中（需要状态机 + 防重复触发） | 1 天 |
| 零重启热更新 | 低（DSH 主进程服务图 / ESM 缓存 / client bundle） | 不建议做 |

## 5. 与 2.7.11 的关系
2.7.11 只做「重启助手更可靠」（按 exe 路径杀 + 日志），保留现有「升级后自动重启」行为；
2.8.x 再按本方案把「重启」改成用户在 UI 上点。两者不冲突：自动重启可保留为「自动安装」开关的一个子选项（默认关）。
