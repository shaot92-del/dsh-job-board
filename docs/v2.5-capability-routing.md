# v2.5 能力路由设计（工作大类 · 可选探测 · ETA 选机）

> 状态：v2.5.0 已实现三项视频探测；其余类别待 v2.5.1。基线 v2.4.3。
> 一句话：把「哪台机器更强」换成「这个任务、这台机器现在跑，预计多久跑完」，并且让用户自己跑一次探测就知道边界。

## 1. 三条原则

1. **能力是「机器 × 工作大类」的矩阵**，不是单机总分。
   GT14 转码 156–182 fps，补帧只有 14.4 fps，两项差一个数量级；不能用一个 `score` 概括。
2. **探测是用户动作，不是定时任务。**
   跑一次要几十秒到几分钟，默认不自动跑；用户点「能力探测」，可勾选类别。v2.5.0 不提供取消（本机同步执行，关窗不中断），取消放 v2.5.1。超过 30 天未测只提示「已过期」，不自动重测。
3. **未测不阻塞，但不能装作知道。**
   v2.5.0 没有实测时**回退最闲机器**，不伪造先验值，也不在回执里写 `routeReason/confidence`（这两项放 v2.5.1）。用户可为高风险任务打开「只许实测机器」（v2.5.1 接线）。

## 2. 工作大类目录（首版 8 类）

| id | 用户看到的名称 | 统一指标 | 探测样本 | 预计耗时 |
|---|---|---|---|---|
| `video.transcode` | 视频转码 / 压制 | 帧/秒（1080p H.264） | 10 秒 1080p 片转 H.264 | 10–20s |
| `video.interp` | 视频补帧 | 帧/秒（1080p 30→48） | 2 秒片补到 48fps | 约 20s（CPU 口径） |
| `video.render` | 合成 / 渲染 | 帧/秒（1080p 无头浏览器） | 240 帧 canvas 渲染 | 20–60s |
| `image.generate` | 图像生成 | 秒/张（512×512） | 连续 2 张 | 20–120s |
| `audio.tts` | 语音合成 | 字符/秒（或 ×实时） | 200 字合成 | 5–20s |
| `llm.text` | 文本 / 代码对话 | token/秒（输入 512） | 生成 256 token | 10–40s |
| `llm.vision` | 视觉理解 | 图/分钟 | 3 张图描述 | 15–60s |
| `io.copy` | 数据搬运 / 磁盘 | MB/秒 | 512MB 顺序写 | 5–20s |

> 类别名可以改，id 不改（任务里存 id）。用户勾选「这台机器主要做哪些工作」只影响 UI 默认展示与探测推荐，不硬性禁止别的任务。

## 3. caps 2.1 数据结构

```jsonc
{
  "schema": 2.1,
  "identity": { "machine": "GT14", "os": "Windows 11", "cpu": "...", "cores": 10, "memGB": 32 },
  "gpu": [{ "name": "RTX 4070", "vramGB": 12 }],
  "tools": { "ffmpeg": { "path": "...", "version": "N-126492", "hw": ["nvenc","qsv"] } },
  "workloads": [
    {
      "id": "video.interp",
      "unit": "fps",
      "value": 14.4,
      "samples": 3,
      "confidence": "measured",          // measured | inferred | declared
      "workload": { "width": 1920, "height": 1080, "fpsIn": 30, "fpsOut": 48 },
      "measuredAt": "2026-11-14T10:00:00Z",
      "benchVersion": 1
    }
  ],
  "limits": { "maxConcurrent": 2, "quietHours": [0, 7], "allowUnverifiedHighRisk": false }
}
```

- 同一 `id` 只保留一条；重测覆盖，旧值进 `history`（最近 10 次，供趋势图，v2.5.1）。
- `confidence` 只由数据来源决定：探测脚本写入 `measured`，人工填写 `declared`，由名称/规格推断 `inferred`（或 `low`）。
- 不用探测结果做鉴权/准入，只用于排序与 ETA。

## 4. 探测流程（面板）

```
机器卡 →「能力探测」
  1. 勾选类别（默认：这台机器已声明的重点类别；全选显示预计总耗时）
  2. 开始 → 任务落到该机器执行（exec 模式，脚本自带进度文件）
  3. 面板显示当前类别与已用时间；v2.5.0 无取消（关窗不中断），取消放 v2.5.1
  4. 完成 → 结果表（各项数值、confidence、与上次对比）
  5. v2.5.0 由探测路由直接写回本机能力卡（旧卡读不到就不写）；“先确认再保存”放 v2.5.1
```

- 探测脚本：`scripts/probe-workload.ps1 -Workload video.interp -Out <json>`，每类一个固定小样本；失败只标记该类 `failed`，不影响其它类。
- v2.5.0 在本机同步跑（`execFile` pwsh），关掉面板不影响；取消与远程执行放 v2.5.1。
- 读不到旧卡时直接 503 不写，避免浅合并覆盖 identity 与其它类。

## 5. 路由（board_dispatch）

输入：`taskKind`（映射到 workload id）、`size`（帧数/字数/图数）、可选 `model`。

1. **准入**：`requires` 硬过滤（已有）。`onlyMeasured`（只允许实测机器）放 v2.5.1。
2. **估时**：`eta = size / value + 8s`；v2.5.0 无实测时回退“最闲”，先验与低置信标注放 v2.5.1。
3. **选择**：在通过准入的机器里取「预计完成时间最早」的一台；并行拆分按 wall-clock 取 max，不按总吞吐。
4. **稳定阈值**（已确认）：
   - 两台 ETA 差 ≤ 15% → 不换机，避免抖动；
   - 单任务**计算时间** < 2s（不含 8s 固定开销）→ 不跨机，保持 ETA 最短的机器。
5. **回执**：v2.5.0 只在 `board_dispatch` 的回执里带 `workload/size/etaSeconds`（建单 payload 未变）；任务字段与 `routeReason/confidence` 放 v2.5.1，历史回写放 v2.5.2。

## 6. 与「模型选择」的关系

- `llm.text` / `llm.vision` 的 workload 是「机器级」吞吐；具体模型仍由 `model` 字段选择（v2.1.0 已有）。
- 模型清单里的 `tags` 负责「哪类任务适合」，workload 负责「这台机器跑这类任务多快」；两者不混。
- 用户打开「允许未验证模型承担高风险」时，路由仍按实测 ETA 排序，但回执标 `policy: user-override`。

| 版本 | 内容 | 验收 |
|---|---|---|
| **v2.5.0** | 工作大类目录 + caps 2.1 + 面板「能力探测」（先做 `video.transcode` / `video.interp` / `video.render` 三类）+ ETA 选机 + 阈值（≤15%、计算时间 <2s 不跨机） | 三台机器各跑一次探测；不探测时行为与 2.4.3 一致。68 段补帧的 wall 误差 <5% 验收放 v2.5.2（需真实任务历史） |

## 8. 非目标

- 不做跨机迁移中的任务（task 一旦 claimed 不换机）。
- 不做「自动定时基准」；不做跨网络吞吐探测（Z: 网络盘单列，不混进本机 io）。
- 不把探测结果当安全边界；高风险开关仍是显式用户选择。

## 9. 已确认（2026-11-14）

1. 8 类目录按此命名，id 固定。
2. 首版只做视频 3 类探测（安全考虑，先跑通再扩）。
3. 入口用独立「能力探测」，与机器卡的能力卡配置分开；首版只测本机。
